# 避障实现方案（讨论稿）

> 需求：人为干扰下，车不止「遇障停下」，还要「绕过去继续绕八字」。
> 本文只谈思路和设计，不写代码。等确定方案后再实现。

---

## 一、约束与难点

| 约束 | 影响 |
|---|---|
| 传感器只有 Livox Mid-360（360° 3D 雷达） | 只能靠点云感知障碍物，没有相机/超声波 |
| 车是全向平移底盘（不转向，wz 忽略） | 绕障靠平移，不靠打方向盘 |
| 任务是固定路线绕八字（7 状态机） | 避障不能破坏既有状态机流程 |
| 障碍是「人突然挡路」 | 障碍会动、会突然出现，不能假设静态 |
| 评分要「绕过去」而非「停下」 | 需要真正的绕行，不是急停 |

---

## 二、核心思路：避障只在「速度层」修正，不打断状态机

现在 figure8 的控制链是：

```
状态机(7状态) → 控制律 → v_target(目标速度) → R_bc → SafeCmd → 19字节帧
```

加避障后，在「控制律」和「R_bc」之间插一层**避障层**：

```
状态机(7状态) → 控制律 → v_target
                          │
              ┌───────────▼───────────┐
              │ 避障层：前方有障碍吗？  │
              │  无 → v = v_target    │
              │  有 → v = 绕行速度     │
              └───────────┬───────────┘
                          ▼
              v → R_bc → SafeCmd → 19字节帧
```

**为什么这样设计**：状态机完全不知道避障这回事，它还在原来的状态（比如 OrbitDown
绕下桩）。避障只是「这一帧把速度改一下」，车朝旁边让一下。绕过之后前方清空，
`v` 又变回 `v_target`，车继续绕桩。**任务语义全程不被打断**。

---

## 三、障碍物检测（复用桩检测的聚类）

我们已经有一套桩检测（`pile_detect.cpp`），避障可以**复用它的聚类函数**：

1. 把雷达点云投影到水平面（和桩检测一样）；
2. 用 `cluster_points` 聚成若干簇；
3. **排除桩**：簇的圆心如果和已知桩位置（桩检测已给出）很近，就丢掉；
4. 剩下的簇就是**障碍物**（人）。

区分「桩」和「人」的判据：
- 桩：已知半径 0.08m，圆拟合能匹配上，且位置和桩检测结果一致；
- 人：半径/尺寸明显更大（约 0.4~0.5m），圆拟合匹配不上 0.08m 的桩。

> 顺带：障碍物检测可以作为 `pile_detect.cpp` 的姊妹函数 `detect_obstacles`，同样放 core/ 写单测。

---

## 四、判断「是否挡路」（避免误触发）

不是「有障碍物就绕」，而是「障碍物挡在我的前进方向上才绕」。判断方法：

- 取当前目标速度 `v_target` 的方向 θ；
- 检查车前方一个**扇形区域**（比如 θ ± 45°，半径 0.5m）内有没有障碍物点；
- 有 → 触发避障；没有 → 忽略（障碍物在旁边/后面，不影响）。

这样能避免：障碍物在车旁边时车乱动。

## 五、绕行算法（两个方案）

### 方案 A：人工势场法（最简单，几行公式）

```
v = v_target - k_rep * Σ (1/d_i) * u_i
```

- `d_i`：车到障碍物点 i 的距离；
- `u_i`：从障碍物指向车的单位方向（背离障碍物）；
- `k_rep`：斥力增益。

含义：每个障碍物点产生一个「斥力」，距离越近斥力越大。当障碍物在前方时，斥力把
`v_target` 往旁边推，车自然偏转绕开。

- ✅ 优点：实现极简（纯 C++ 十几行），速度快平滑；
- ❌ 缺点：可能「局部极小值」——障碍物正好挡在车和目标中间时，斥力（推开）和
  目标引力（往前）抵消，车卡住不动。对「人」这种会动的障碍不太致命，但理论上存在。

### 方案 B：沿障碍物切向绕行（推荐，更可控）

思路：触发避障后，不再朝目标走，而是**贴着障碍物边缘沿切向绕**，保持安全距离。

```
1. 找障碍物最近点 P，距离 d；
2. 确定绕行方向：障碍物质心在 v_target 方向的左侧 → 朝右绕；右侧 → 朝左绕；
3. v_avoid = v_t * t  +  k * (d - d_safe) * n
     t = 沿障碍物切向（绕行方向）
     n = 背离障碍物方向（保持安全距离 d_safe）
```

- ✅ 优点：绕行方向明确、不会卡死，一定能绕过去；
- ❌ 缺点：要处理「选绕行方向」「切向怎么算」「什么时候算绕过」几个细节，比势场法复杂。

**推荐方案 B**，因为需求明确说「要绕过去继续任务」，方案 B 的确定性更强，也更符合
「全向平移」的特点（平移车可以贴着障碍物侧向滑过去）。

## 六、恢复条件（怎么算「绕过去了」）

避障是临时的，需要一个「退出」条件：

- 检查前方扇形区域是否已经清空（没有障碍物点了）；
- 清空 → `v` 恢复为 `v_target`，避障结束，继续原任务。

要注意加**滞回**：进入避障和退出避障的阈值不同（比如进入时距离 < 0.4m，退出时
距离 > 0.6m），否则车会在阈值附近来回抖。

---

## 七、安全兜底：绕不过去就停下

即使绕行，也可能遇到「障碍物贴脸」或「被墙堵死」的极端情况。所以避障层要保留
「急停」作为最后手段：

- 距离 < 0.2m（很近）→ 直接输出零速（停下），等障碍物离开再继续；
- 距离在 0.2~0.5m → 绕行；
- 距离 > 0.5m → 正常走。

这样「停下」是最后兜底，不是默认行为，符合「优先绕、绕不过才停」。

## 八、实现步骤建议（确定方案后照着做）

1. core/ 加 `detect_obstacles()`（聚类 + 排除桩），写单测；
2. core/ 加 `avoid_step()`（纯函数：输入 v_target、障碍物点集，输出修正后的 v），写单测；
3. figure8 的控制链里，`target_velocity` 之后插入 `avoid_step`；
4. 模拟里加「障碍物模型」（Gazebo 放一个可移动的柱子/盒子，手动推着挡车）；
5. RViz2 里显示障碍物簇，肉眼确认绕行轨迹。

## 九、难点与坑（提前想到的）

1. **桩和障碍物别混淆**：绕桩时桩就在旁边，如果没排除桩，车会「躲桩」，任务就毁了。
   所以「排除桩位置附近的点」是硬要求。
2. **障碍物会动**：人可能朝车走来。绕行方向可能中途失效，需要每帧重新判断。
3. **绕行时状态机还在走**：比如绕下桩时被挡，绕行会让车偏离圆轨迹，累积绕行角会
   受影响。可以考虑「避障期间冻结累积角」或「避障期间状态机只保持不切换」。
4. **抖动**：进入/退出避障要加滞回，否则车在障碍物边缘左右抖。
5. **性能**：点云聚类已经 O(n²)，避障要复用同一套聚类结果，不要每层都重新聚一遍。
